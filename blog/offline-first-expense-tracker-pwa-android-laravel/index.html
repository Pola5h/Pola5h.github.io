Building an Offline-First App with Zero-Cost AI on a 256MB Server

How I designed Hishab: a practical personal cashflow tracker, tenant rental manager, and zero-cost Gemini AI expense engine with Vue 3, Laravel 13, and a dedicated Android WebView wrapper on a 256MB RAM host.

KP
Kamruzzaman Polash
October 21, 2026

Mainstream personal finance applications are built around enterprise double-entry ledgers: you declare every bank account, reconcile mobile wallets, and record internal transfers whenever you withdraw physical cash. For me, that overhead broke the logging habit within weeks. I did not need to reconcile bank balances across five portals. I needed a frictionless cashflow monitor: log income when it arrives, record daily living expenses the moment they occur, track multi-unit rental leases, and split shared apartment utility bills fairly.

I built Hishab to solve these real-world problems. The entire system runs on a shared Linux container with a strict 256MB RAM cap (0.25 vCPU) and zero monthly cloud bills. It combines a local-first Vue 3 Single Page Application, a hardened native Android WebView wrapper, and a lean Laravel 13 backend powered by SQLite and zero-cost Gemini AI expense parsing.

1. Single Cashflow & Arbitrary Category Depth

Commercial budgeting apps (YNAB, Monarch) cost $100 to $120+ annually and restrict users to flat, two-level categories. Real personal finances require deep, layered granularity (e.g. Personal > Family > Son > Health > Medicine). Hishab eliminates multi-account balancing completely, focusing strictly on money in versus money out with high-resolution classification:

  • Arbitrary Category Depth: The category tree supports unlimited nesting levels. Child transactions automatically roll up to their ancestors in high-level reports while allowing multi-level drill-downs.
  • Constant Baseline Budgeting: Instead of re-entering zero-based budgets every 30 days, Hishab sets a steady spending baseline. This immediately surfaces real seasonal surges (such as Eid, Puja, or medical emergencies) as actionable percentage spikes (e.g. +180% surge) rather than administrative friction.
  • Dynamic Bottom-Up Budget Rollup: When child category budgets exceed their parent's direct target, the parent dynamically expands upward to the root level. When a parent target exceeds its children, the difference is tracked as an unallocated_buffer without validation roadblocks.
  • Historical Boundary Scoping: Adjusting a past month's budget isolates that specific month and never bleeds forward into current or future baselines.

2. Rental Management: Bill Splits & FIFO Reconciliation

Managing residential rental properties involves two frequent points of tenant friction: dividing shared utility invoices and applying partial rent payments.

  • Deterministic Utility Bill Splits: When a building receives a shared utility bill (water, gas, electricity), integer arithmetic calculates each unit's base share. Any remainder poishas are allocated deterministically to units sorted by their unique IDs. The math is reproducible to the penny, preventing rounding losses or unbalanced tenant statements.
  • FIFO Lease Balance Reconciliation: Tenants frequently pay in irregular installments. The reconciliation service applies payments in strict First-In-First-Out (FIFO) chronological order, settling oldest unpaid rent charges before applying funds to current utility dues.
  • Automated Domain Testing: Financial calculations require rigorous mathematical verification. The engine is backed by a 74-test automated suite (540+ assertions) testing remainder poisha distributions, multi-month arrears settlements, and 5-level recursive budget rollups.

3. Architectural Efficiency: Running on 256MB RAM

Running production Laravel 13 on a shared Linux container with a strict 256MB RAM cap and 100MB disk quota required deliberate architectural choices:

  • SQLite in WAL Mode (0 MB Idle Resident Memory): Traditional MySQL/PostgreSQL instances consume 120MB+ just idling for connections (though for higher-concurrency systems, proper MySQL query optimization and connection tuning remain essential). Hishab uses SQLite configured with Write-Ahead Logging (PRAGMA journal_mode=WAL;) and a 5,000 ms busy timeout. Readers never block writers and writers never block readers. Standby memory is 0 MB, and scheduled daily backups read clean snapshots without table locks.
  • Stateless PHP-FPM Execution: With cached configuration, routes, and views, PHP-FPM boots on demand, handles the request in milliseconds, and immediately releases memory back to the OS.
  • Client-Side Rendering (SPA): The compiled Vue 3 Single Page Application is served as static files. All chart math, aggregations, and tree filtering execute on the client device, keeping server CPU usage near zero.
  • Deep Health Monitoring: A dedicated /api/health/deep endpoint verifies database integrity, storage permissions, and backup freshness on every deployment.

4. Mobile: Offline-First PWA to Hardened Android Shell

Expense logging occurs on the move, requiring immediate response even with zero cellular signal.

  • Offline Outbox & Web Locks: Client records save instantly to IndexedDB with optimistic UI updates. When network connectivity returns, a background worker flushes the queue via idempotent PUT requests following clean REST API design principles. Browser Web Locks guarantee that only one browser tab flushes the sync queue at a time.
  • Conflict Resolution (LWW & Tombstones): Every entity receives a client-generated UUID (v4) on creation. Sync conflicts resolve via Last-Write-Wins (LWW) using millisecond-precision updated_at timestamps. Deletions apply a deleted_at tombstone so that deleted records propagate across offline devices without accidental resurrection.
  • Why Custom WebView Beat TWA: Trusted Web Activities (TWA) occasionally failed digital asset verification on slow mobile networks, unexpectedly showing URL address bars, and lacked dynamic system bar theme tinting. A custom native Android WebView wrapper provided complete control: hardware back button routing, native pull-to-refresh coordination, biometric authentication, and bidirectional system bar recoloring.
  • Native Shell Integration: The wrapper enforces strict origin whitelisting (loading only the trusted HTTPS production host and dispatching external links to the system browser), handles hardware back-button navigation, coordinates native pull-to-refresh with web scroll containers, and bridges live theme and scroll states directly to Android system window insets via @JavascriptInterface.

5. Zero-Cost Natural Language AI Expense Parsing

Logging multi-item bazaar receipts (e.g. "চাল ২০০, ডাল ৫০০, রিকশা ৫০, বাবুর ঔষধ ৬০০") via manual form dropdowns causes input fatigue. Hishab turns raw colloquial text into validated ledger records instantly.

  • Zero-Cost Architecture: Running local LLMs (Ollama) was impossible on a 256MB container. Instead, Hishab leverages Google Gemini's free tier (15 requests/min on Flash models, per official Google AI docs), introducing 0 MB server memory overhead and zero API cost.
  • Two-Phase Hybrid Pipeline: Phase 1 injects the user's active CategoryTree path taxonomy and Banglish phonetic rules into a structured system prompt. Phase 2 applies deterministic PHP guardrails: foreign key validation, word-boundary checks, and partial-cost deduction arithmetic. Unmapped items are safely skipped rather than assigned to random categories.
  • Multi-Model Fallback: The pipeline attempts gemini-2.5-flash-lite first. On rate limits (HTTP 429) or timeouts, it automatically falls back to gemini-2.5-flash (for production multi-provider failover patterns across OpenAI, Claude, and Gemini, see my guide on the Laravel AI SDK and OpenRouter). If completely offline, the raw note is preserved and transferred directly into the manual Quick Add modal without data loss.
  • Privacy Boundaries: The AI payload contains strictly the raw note text and category path taxonomy. Account balances, bank names, account numbers, tenant records, and property addresses are never sent to external LLMs.
  • Interactive Review: Parsed items render in an interactive preview modal where deduced amounts are visually tagged. The user can tweak any single field and commit the entire batch with a single confirmation tap.

6. Core Engineering Takeaways

  1. Solve your own friction first: Commercial budgeting tools suffer from enterprise feature bloat. Designing software specifically around your own daily routine creates applications you will actually use for years.
  2. Resource limits breed better architecture: Operating inside a 256MB container forced the elimination of background daemons, leading to a lightweight, zero-maintenance SQLite architecture that outperforms bloated MySQL setups.
  3. Pragmatic mobile bridges win: A lightweight native Android wrapper around a well-tuned offline PWA provides native hardware capabilities without the development friction of separate codebase rewrites.
  4. Target AI where it removes real friction: You do not need multi-agent frameworks or expensive GPU servers to build real utility. Pairing a free-tier LLM API with deterministic backend guardrails eliminates everyday logging fatigue while keeping infrastructure lean.

Hishab manages my personal cashflow and rental property accounts every day. If you are building local-first applications or optimizing SaaS architectures for lean infrastructure, focusing on clear domain boundaries and ruthless simplicity will always pay dividends.
